## 2. 现有视觉风格分析与统一设计规范

以下规范是所有智能体的**公共契约**，任何页面不得违反。

### 2.1 设计气质

「冷白屏幕里的一台精密仪器」：冷白底 + 墨色文字 + 亚克力外框，信息密度克制，拟物细节（键面、浮雕、凸边）统一受一束 118° 光照。青绿只用于「活着的状态」，朱砂只用于「需要被指出的编号」。

### 2.2 色彩（theme = cool，唯一主题）

| 用途 | 值 | 规则 |
|---|---|---|
| 底色 bg | `#F2F5F7` | 页面底 |
| 卡面 surface | `#FFFFFF` | 比底亮一档，卡才浮得起 |
| 框/图框 frame | `#D6DEE3` | 比底深一档 |
| 正文 fg | `#12171A` | |
| 说明 fg-dim | `#4C565C` | |
| 等宽标签 fg-faint | `#5C666C` | 日期、编号、状态行 |
| 状态·活 live | `#00605E`；实底 `#00827F`（只配白字） | 在跑/可试玩专用 |
| 标记 mark | `#8B2C1F` | 作品编号、需要指出的一处 |
| 细线 line / line-strong | `#CBD6DB` / `#B9C5CC` | |
| 铭牌淡彩 | 青 `#CFE3E0` 朱 `#E8D3CE` 钢 `#D7E0E5` 天 `#D3E8F5` 沙 `#E7DDCB` | 铭牌右半底色 |
| 受光渐变 | 118°：白 .75 → 白 .06（中）→ 墨 .05（端） | 所有凸面、键面、卡面同向 |

### 2.3 字体与字号

- 字体栈：sans = PingFang SC / Microsoft YaHei / Source Han Sans SC；大标题可用 Arial Black 系；mono = Cascadia Code / JetBrains Mono / Consolas，**只装数字与短标签**。
- 字号只有六档：t0 `clamp(60,9.6vw,140)` / t1 `clamp(34,4vw,56)` / t2 `clamp(24,2.4vw,34)` / t3 `17px` / t4 `15px` / t5 `13px`。设计稿按 1440 宽度取各档上限近似值：t1≈56、t2≈34。
- 作品页主标题用 t1，不超首页主名的规格（首页主名是全站最大字，作品页不可僭越）。

### 2.4 布局与间距

- 间距基准 8：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128`。
- 内容宽 `--wrap: 1240px`，页边距 `--pad: 44px`。
- 页面壳三层（所有页面共用，缺一不可）：**亚克力外框 bezel**（墨色、118° 受光、内圆角 4px）→ **纸面 sheet**（冷白）→ **药丸顶栏**（两枚 chip，当前页为墨色亚克力片，白字）。
- 章头 `.sec-head`：居中，编号 + 标题。
- 页脚：`© 2026 ZLOONG · Dragonzhi` + `闽ICP备20260330551号-1`（**法务，不得删改**）。

### 2.5 组件规范

1. **药丸 chip**：圆角全圆；当前页 = 墨色亚克力三段面（`#2A3035` / `#1B2024` / `#12171A`）+ 白字；非当前 = 透明底 + fg-dim 字。
2. **软 UI 卡**：白面 + 外圈凸边（上暗 `#C3CED5`、下亮白）+ 内面极淡冷色内发光；圆角建议 12–16。
3. **铭牌键 badge**：Shields flat-square 形——左侧墨色键 `#161D28` 白字（mono 短标签），右侧淡彩色面深色字；2px 圆角，26px 高，宽随内容。
4. **状态灯**：小圆点 + mono 状态字。在跑 = 青 `#00605E`；在制 = 墨；归档 = 沉（fg-faint）。**三态是内容，不是装饰**。
5. **浮雕字**：仅首页主名使用，作品页不重复此效果（避免通货膨胀）。
6. **字符浪潮**：作品页页首可用**矮浪带**（同 `js/wall.js` 调淡版）作为页面识别元素——设计稿中表现为一条低幅的墨色字符纹理横幅。

### 2.6 动效与交互（设计稿需标注，不实现）

- 指针微动：卡面/铭牌悬停倾斜 ≤7°，离开归位。
- 链接悬停：颜色过渡 .12s，ease `cubic-bezier(.2,.7,.3,1)`。
- 尊重 `prefers-reduced-motion`；不劫持滚动；动效须能一句话说清表达什么。

### 2.7 响应式

五档 1440 / 1024 / 768 / 390 / 320，零横向溢出。≤768 卡片单列、顶栏保持两枚 chip 不换行溢出、t 档字号自动收窄。

## 6. 同一 `.pen` 文件的协作与冲突规避方案

**前提判断**：不假设 pen.dev 支持安全的多智能体并发写同一文件。采用「**准备并行、落笔串行**」策略：

1. **命名与分区契约**
   - 页面命名固定：`00-STYLE`、`01-WORKS`、`02-WORK-DETAIL`。
   - 每个页面是一个顶层 Frame；智能体**只准在自己 Frame 内部创建/修改图层**，不得移动、缩放、重命名他人的 Frame。
   - 图层命名前缀：`S-`（规范页）、`W-`（总览）、`D-`（详情），如 `W-card-01-cover`。
2. **共享规范的传递方式**：公共规范**不靠共享组件实例**，而靠 Page 0 样张 + 本规划 §2 的数值表。各页面**复制**样张元素后自行改造，禁止跨页面引用同一实例（避免一处改动连环污染）。这牺牲了一点「改一处全改」的便利，换来零并发冲突。
3. **时序**：
   - 阶段 2（串行）：仅总协调 A 落笔——建文件、建 Page 0、建两个空页面 Frame、保存。
   - 阶段 3（准并行）：B1、B2 **先各自完成设计方案的完整细化（布局计算、文案落位、图层清单），写入各自的执行回执**；随后由弱模型调度**串行落笔**——B1 先画总览页，保存并报告完成；B2 再画详情页。若执行环境证实支持并发编辑同文件不同 Frame，可改为真并行；否则串行，宁可慢不可乱。
   - 阶段 4–5（串行）：A 通查 → C 质检 → 问题单回流 → B 修 → A 验收。
4. **检查点**：每次落笔阶段结束必须保存文件并报告「已完成图层清单 + 未决问题」，弱模型据此决定下一步调度。
5. **冲突兜底**：若发现他人 Frame 被误动，停止该智能体，由 A 从最近检查点恢复/重建该 Frame。
