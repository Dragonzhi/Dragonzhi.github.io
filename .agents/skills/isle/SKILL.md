# 案屿 · 项目交接

项目根目录是本规范所在 `.agents/skills/isle/` 向上的三级目录。先读取该目录的 `TASKS.md`，以用户本次指定的项目和工作范围为准；不要把当前终端所在的子目录或其他项目当成目标。文件缺失、存在多份交接摘要或目标不明确时，先与用户确认，不重建或猜测覆盖。

本 Skill 只约定读取与回写项目记录，不授予实现、运行测试、提交、推送或调用其他 Agent 的额外权限。不要修改 Skill、项目规则或无关文件。

## 开工

- 读取完整 `TASKS.md`：状态、next、三个任务分节；历史与「为什么」读 `DECISIONS.md`。当前有效状态以 next 与任务清单为准。
- 用户本次目标和完成标准优先。列表首个进行中／待办只是参考，不等于已授权任务；未验证的旧结论仍需核实。不依赖上一家 Agent 的聊天记录。
- 用户要求复核时，动手前先说明三件事：读到的现状、认为依据不足或可能已被后续推翻的既有结论、打算怎样验证。说明之后再按本次目标继续。
- 目标不明确或只有等待事项时询问用户。按用户授权继续工作，结束或被要求交接时再执行收工。

## 篇幅预算

记录是给下一位 Agent 的索引，不是工作日志。每句先问：删掉它，接手的人会不会做错事？不会就删。

- `next`：一句话，50 字内。
- 已完成：一条一行，只写做了什么；标题末尾记 `（YYYY-MM-DD）` 完成日期。只保留最近 14 天且最多 40 条，超出按日期从旧到新删除（历史见 `DECISIONS.md` 与 Git）。
- `DECISIONS.md`：一条一事，只写「为什么变成这样」与代价；同一天同一主题的多轮调整合并成一条，不写逐次流水。

超预算先删修饰、过程与文件清单，再合并同义句；不删事实——变更要点、验证结果、「未验证」、阻塞和下一步必须留下。实现细节、路径清单、命令与截图交给 PR、`DECISIONS.md` 和设计文档，记录里只留一句指向。

## 收工回写

停止新增工作，只整理本次会话已经发生的结果。不要为补齐收工记录继续实现、补跑验证或提交代码。先重新读取文件，保留他人的改动，然后按顺序维护以下内容：

1. **任务清单**：维护 `## 待办`、`## 进行中`、`## 已完成`，缺少时才补上。未开始的具体行动用 `- [ ]` 放待办，已开始但未达标的放进行中；只有实际达到完成标准的任务才用 `- [x]` 并移到已完成。部分完成、阻塞、验证失败都保留未完成状态。本轮实际处理但尚未列出的工作应补入相应分节，明确的下一步行动进待办；已有相同任务则更新或移动原条目，保留标签和无关任务，不重复新增。每条一行，只写行动或结论，已完成不写验证过程。任务完成时在标题末尾写 `（YYYY-MM-DD）`；`## 已完成` 超出最近 14 天或 40 条时从最旧条目删起，历史以 `DECISIONS.md` 与 Git 为准。纯讨论且没有行动项时可以不改任务，并说明原因。
2. **决策记录**：只有本次确立或推翻了设计 / 技术判断时才写 `DECISIONS.md`，按时间倒序在顶部追加一条，写清「定 / 理由 / 代价」；例行实现、文案与参数微调不写。被推翻的旧判断不删，由新条目说明取代关系。
3. **续接与日期**：next 写「停在哪里；下一步做什么」，updated 使用回写当天本地日期 `YYYY-MM-DD`。不凭首条任务猜测完成情况，不清空仍有效的信息。

已有任务记录明显超出预算时，可在回写时一并压缩措辞；压缩保留日期、结论与「未验证」，不改事实、不删仍在起作用的阻塞与下一步。

`TASKS.md` 只保留 `## 待办` / `## 进行中` / `## 已完成` 三节，不新增摘要或留痕分节；历史与原因写进 `DECISIONS.md`。

保留原有编码、换行和无关内容。保存前再次核对读取后的文件是否被外部修改；有冲突先停止，不覆盖其他改动。保存后重新读取，核对任务清单与 next 是否一致。

回复说明任务清单的变更或不变原因、本轮是否有 `DECISIONS.md` 条目及理由、实际验证与未验证内容、下一步。
