# 案屿 · 项目交接

项目根目录是本规范所在 `.agents/skills/isle/` 向上的三级目录。先读取该目录的 `TASKS.md`，以用户本次指定的项目和工作范围为准；不要把当前终端所在的子目录或其他项目当成目标。文件缺失、存在多份交接摘要或目标不明确时，先与用户确认，不重建或猜测覆盖。

本 Skill 只约定读取与回写项目记录，不授予实现、运行测试、提交、推送或调用其他 Agent 的额外权限。不要修改 Skill、项目规则或无关文件。

## 开工

- 分层读取 `TASKS.md`：先读 `status`、`next` 与三个任务分节；交接摘要只读最近 3 节（文件内本就应只有 3 节），更早的节只是历史索引，与 next 或任务清单冲突时以 next 与任务清单为准；工作留痕只看当前视窗（最近 14 天且最多 12 条）。必要时核对用户目标相关的工程状态。
- 用户本次目标和完成标准优先。列表首个进行中／待办只是参考，不等于已授权任务；未验证的旧结论仍需核实。不依赖上一家 Agent 的聊天记录。
- 用户要求复核时，动手前先说明三件事：读到的现状、认为依据不足或可能已被后续推翻的既有结论、打算怎样验证。说明之后再按本次目标继续。
- 目标不明确或只有等待事项时询问用户。按用户授权继续工作，结束或被要求交接时再执行收工。

## 篇幅预算

记录是给下一位 Agent 的索引，不是工作日志。每句先问：删掉它，接手的人会不会做错事？不会就删。

- `next`：一句话，50 字内。
- 交接摘要：本轮 2–4 条，每条 60 字内。
- 工作留痕：一条一行，80 字内（日期与署名不计）。
- 已完成：一条一行，只写做了什么；标题末尾记 `（YYYY-MM-DD）` 完成日期。只保留最近 14 天且最多 40 条，超出按日期从旧到新删除（历史见工作留痕、验收记录与 Git）。

超预算先删修饰、过程与文件清单，再合并同义句；不删事实——变更要点、验证结果、「未验证」、阻塞和下一步必须留下。实现细节、路径清单、命令与截图交给 PR、`验收记录.md` 和设计文档，记录里只留一句指向。

## 收工回写

停止新增工作，只整理本次会话已经发生的结果。不要为补齐收工记录继续实现、补跑验证或提交代码。先重新读取文件，保留他人的改动，然后按顺序维护以下内容：

1. **任务清单**：维护 `## 待办`、`## 进行中`、`## 已完成`，缺少时才补上。未开始的具体行动用 `- [ ]` 放待办，已开始但未达标的放进行中；只有实际达到完成标准的任务才用 `- [x]` 并移到已完成。部分完成、阻塞、验证失败都保留未完成状态。本轮实际处理但尚未列出的工作应补入相应分节，明确的下一步行动进待办；已有相同任务则更新或移动原条目，保留标签和无关任务，不重复新增。每条一行，只写行动或结论，已完成不写验证过程。任务完成时在标题末尾写 `（YYYY-MM-DD）`；`## 已完成` 超出最近 14 天或 40 条时从最旧条目删起，历史以留痕与 Git 为准。纯讨论且没有行动项时可以不改任务，并说明原因。
2. **交接摘要**：每轮在 `## 交接摘要` 下新起一个 `### YYYY-MM-DD 标题` 节，按「变更要点 → 依据 → 验证结果 → 未完成或阻塞」写，同一事实只写一次，不复述留痕。变更只写动过的对象和结果，能核对到的才写；为什么这样改、证据到哪一步（读过代码、复现过、还是只是怀疑）写进依据，不塞进变更。发现旧结论已被推翻时就地补一行 `> 已失效：由 YYYY-MM-DD 更正`，保留原文不删。写清接手的第一个动作。没做的验证明确写「未验证」；不把尝试写成结论，不倾倒聊天记录。摘要不能替代任务清单。带日期的轮次节只保留最近 3 节，超出的从最旧删起；删除前必须把仍起作用的事实（阻塞、未验证、下一步）并入最新节或任务清单，历史由 Git 与验收记录承载。不带日期的节（仍在起作用的接手注意）可以保留，不计入 3 节。
3. **工作留痕**：向 `## 工作留痕` 末尾追加本轮贡献，只保留最近 14 天且最多 12 条，超出从最旧删起，历史由 Git 承载。格式为 `- YYYY-MM-DD · 署名：做了什么；验证结果或未验证。` 一条一行，不列文件路径、不堆测试项清单、不复述摘要。同一天同一署名的多轮改动，合并到当天该署名那一条；跨天或更换署名再起新条目。部分推进也记录；同一轮收工不重复追加，无新贡献时说明原因。署名采用用户本次指定的 Agent 名称；未指定时先确认，不猜模型名称。任务的 `@标签` 表示原计划接手方，不能据此推断实际作者或替别人补签。
4. **续接与日期**：next 写「停在哪里；下一步做什么」，updated 使用回写当天本地日期 `YYYY-MM-DD`。不凭首条任务猜测完成情况，不清空仍有效的信息。

已有记录明显超出预算时，可在回写时一并压缩措辞；压缩保留日期、署名、验证结论与「未验证」，不改事实、不合并不同日期或署名、不删仍在起作用的阻塞与下一步。

二级分节标题固定，不追加日期、署名或说明；日期写元数据或留痕正文。已有 `## 交接摘要（YYYY-MM-DD）`、英文括号版本或带日期的工作留痕时维护原分节，不另建同名分节。重复的 `## 交接摘要` 二级分节先与用户确认如何合并，不按日期丢弃其中一份；摘要内部的带日期 `###` 轮次节按 3 节窗口滚动，两者不冲突。摘要可用正文、列表、闭合代码块和 `###` 小标题。

保留原有编码、换行和无关内容。保存前再次核对读取后的文件是否被外部修改；有冲突先停止，不覆盖其他改动。保存后重新读取，核对任务、摘要、留痕和 next 是否一致。

回复说明任务清单的变更或不变原因、摘要及留痕记录了什么、实际验证与未验证内容、下一步，并在末尾使用同一署名。如果无法写文件，提供具体任务改动及可粘贴的摘要、留痕，不能声称已回写。
