# 工房 3D 化 · 方向评审与决策记录

> 2026-09 · 记录一次被否决的产出（Trae 的三份「3D 变体」）与随之确定的三方向初稿。
> 相关文件：`.design/README.md`（三份初稿的共享契约）、`.design/case-*.html`。

## 一、背景

计划把 `index.html` 改成 Three.js 的 3D 版本。第一轮由 Trae 产出了三份变体，放在
`.design/workshop-3d-variants/`：`variant-a-paper-depth` / `variant-b-desk-perspective` /
`variant-c-3d-objects`。观感「非常不尽如人意，但说不出问题」。

## 二、实测：三份都不是 Three.js

对全目录 grep `three / THREE / WebGL / canvas / getContext / importmap / WebGLRenderer`：
**.design 下零命中**。用 Chrome 渲染后读取计算样式，实测：

| 变体 | matrix3d 元素 | perspective | CSS 动画 | 实际「3D」是什么 |
|---|---|---|---|---|
| A 纸化深度 | **1**（全页仅 1 个） | 3 | 1 | 鼠标悬停时单张卡 `rotateX/Y ±3deg` + `translateZ(6px)` |
| B 桌面透视 | 13 | 1 | 12 | 整张桌子 `rotateX(3deg)`；卡片 z 位移 20/27px；墙层 `scale(1.08)+translateZ(-120px)` |
| C 3D 物件 | 36 | 4 | 5 | 一个 CSS 立方体（印章 50×50×26，六面坐标正确）+ 若干假纸堆 |

**结论：需求没被执行。** 交付的是同一张 2D 页面的 CSS 皮肤，不是 3D 版本。

## 三、五个根因（「说不出问题」的原因）

1. **3° 在感知阈值之下。** 人眼要十几度的视角变化才读出「空间」；3° + 6px 只读出「卡片动了一下」。
   真 3D 的第一性证据是**遮挡 + 光照 + 阴影**，CSS 一个都给不了。
2. **删掉了全站唯一真正的 3D 交互。** 现首页有 7 个 `data-desk-card`：桌面端可拖卡、位置存
   `localStorage`、可一键还原。三份变体的 `data-desk-card` 均为 **0**。从「我能搬动它」
   退化成「它自己会晃」——能动性下降、表演性上升。
3. **撞上 CSS 3D 的物理天花板。** 没有共享相机、没有光照模型、没有阴影、没有层间遮挡、没有景深。
   造深度只能作弊（B 真的写了 `scale(1.08) translateZ(-120px)`）。CSS 3D 的正确用途是
   **单物件**（C 的立方体），不是**空间**。
4. **版式一点没动。** 三份的 `h1` 都是 62px、版心都是 1040px、令牌一致、段落一致。
   3D 版本该是一次**空间构图**的重做（相机在哪、焦点是什么、什么挡在前景），不是同一列内容加抖动。
5. **断掉了数据流。** 三份全内联脚本、**零 `fetch`**：不读 `files/*.md`、不读 `files-manifest.json`、
   不带 `js/workshop.js`，about/now/links 全部硬编码。落地即与 AGENTS.md 第 2 条冲突
   （改文案要改两处），是分叉而非演进。

工程量方向也反了：A/B/C 是 1210 / 1432 / 1899 行（36.6 / 39.6 / 53.6 KB 单文件），
而现有 `index.html` 只有 259 行 / 14.7 KB——**用 2.5–3.6 倍代码换到了更少能力**。

另：三个「方向」其实是同一方案的三种强度（一张卡抖 3° / 整桌抖 3° / 一个物件抖 18°），
差异只在 CSS 技巧用量，不在「3D 用来干什么」，因此给不出真正的选择。

## 四、决策

1. **删除** `.design/workshop-3d-variants/` 及两个空的 Trae 工作目录（均为未跟踪文件，无 git 历史）；
2. 改为三份**互斥**的方向初稿，回答「3D 用来干什么」：
   - `case-1-physical-desk.html` —— 物理台面：纸卡有厚度、投真实阴影、可拖拽（继承现有台面交互）
   - `case-2-camera-eye.html` —— 镜头即眼睛：相机在场景中前进，纸卡前后遮挡，滚动即推轨
   - `case-3-radio-object.html` —— 单物件：只有 SIGNAL 收音机是 3D，其余保持 2D 纸面
3. **先定方向，再写实现。** 直接出 HTML 会退化成皮肤；3D 的成败在构图与相机。

## 五、遗留决策（需用户定）

AGENTS.md 现写「不引入打包器、框架或 npm 依赖」，Three.js 与这条冲突，三选一：
- **a.** 3D 只做独立页（如 `pages/workshop-3d.html`），首页保持零依赖；
- **b.** 改 AGENTS.md，把 three 记为唯一例外，写清版本 + 加载方式；
- **c.** 放弃 Three.js，只做 CSS 增强。

三份初稿不预设答案，但 `case-3` 天然适配方案 a。
